# Best Prompts for Social Background Images in Nano Banana

## Executive summary

Nano Banana is Google’s family of native image generation and editing models built on Gemini. In the Gemini API, “Nano Banana” refers to multiple model tiers (notably Gemini 2.5 Flash Image for speed, Gemini 3.1 Flash Image Preview as Nano Banana 2, and Gemini 3 Pro Image Preview as Nano Banana Pro), each suited to different production needs. citeturn2view1turn15view0turn2view2

For social background images (banners, story backgrounds, behind-text backdrops), the most reliable prompt strategy is to treat the prompt as a **structured creative brief**: define style/medium, setting, and composition (especially negative space for text overlays), then add constraints (no text/logos/watermarks) and the required aspect ratio. Google’s own guidance emphasizes that **more detail gives you more control**, and explicitly recommends prompting for **production-ready specs** like aspect ratio and format (“widescreen backdrop” or “vertical social post”). citeturn12view0turn3view1

Aspect ratio control is best enforced via the API where possible using `image_config.aspect_ratio` (tokens like `"16:9"`, `"9:16"`, `"1:1"`, etc.). When you can’t set `aspect_ratio` (for example, Firebase AI Logic currently notes this limitation), you should encode the ratio directly in the prompt using the explicit token format (“16:9 aspect ratio”) plus the target use label (“vertical social post”). citeturn16view0turn15view0turn3view1

Color and brand control works best when you (a) name a **tight palette** (primary/secondary/accent), (b) specify **dominance** (“~70% background in…”), and (c) make the composition support that dominance (large gradient field, restrained accents). Official Google examples frequently request a “color palette” / “color scheme,” and the Nano Banana image-generation docs also provide a background-oriented pattern (“Minimalist & negative space design”) that is directly applicable to social backdrops. citeturn16view1turn16view2turn5view0

The report below provides: reusable prompt templates, 24 copy/paste example prompts across industries/ratios/colors/cities/styles, a comparison table of prompt variants and expected outcomes, and a short test checklist with evaluation metrics.

## What Nano Banana is and what the official prompt surface supports

### Model family and when it matters for “social background” work

Google positions Nano Banana models as native image generation/editing capabilities under Gemini (multiple “tiers” with different strengths), and the Gemini API documentation explicitly recommends choosing the model based on use case. Nano Banana Pro (Gemini 3 Pro Image Preview) is oriented toward professional asset production and complex instructions (including high-fidelity text), while Nano Banana (Gemini 2.5 Flash Image) is optimized for speed/efficiency and lower-latency workflows. citeturn2view1turn2view2

For social background images specifically, model choice typically follows a simple decision rule derived from official positioning:
- If you need **design-precise layouts** (especially embedded typography inside the image), Nano Banana Pro is generally the safest choice because it’s described as the professional “asset production” model with stronger text rendering. citeturn16view2turn16view3turn2view1  
- If you need **fast iteration on multiple background variations**, Nano Banana (2.5 Flash Image) or Nano Banana 2 (3.1 Flash Image Preview) is often more cost/latency efficient. citeturn16view3turn2view1turn2view2

### Official guidance on prompt structure for images

Google DeepMind’s Nano Banana prompt guide frames prompts as a set of controllable “dimensions”: **Style**, **Subject**, **Setting**, **Action**, and **Composition**, and stresses the practical point that adding detail increases alignment with what you imagine. citeturn12view0turn12view2

For social backgrounds, **composition** is the critical lever: you’re usually optimizing for a readable overlay region (negative space) and a predictable focal area. This is also reinforced by Google’s Gemini API image-generation documentation, which explicitly calls out “Minimalist & negative space design” as “excellent for creating backgrounds … where text will be overlaid,” and provides a reusable template. citeturn16view1

### Aspect ratio control: official “tokens” and exact syntax

You have two “officially grounded” control paths:

If you are calling via the Gemini API, you can directly set `image_config.aspect_ratio` (and for some models `image_size`). The docs list supported aspect ratio tokens, including: `1:1`, `2:3`, `3:2`, `3:4`, `4:3`, `4:5`, `5:4`, `9:16`, `16:9`, and `21:9`. citeturn16view0turn16view3turn4view1

If you are writing prompts in an environment where you can’t set explicit aspect ratio configs (Firebase AI Logic currently calls this out), you should encode aspect ratio in the text prompt. DeepMind’s prompt guide explicitly recommends prompting for “your desired aspect ratio (like 4:3, 1:1, or 9:16)” and adding a format cue such as “widescreen backdrop” or “vertical social post.” citeturn3view1turn15view0

## Encoding the input dimensions in prompts for social background images

This section answers the “how do I encode each input dimension?” question as a practical grammar you can reuse. The key idea is to **separate creative description from constraints** so the model can “compose” the scene first, then obey guardrails.

```mermaid
flowchart TD
  A[Inputs] --> B[Prompt brief]
  A --> A1[Ratio]
  A --> A2[Industry]
  A --> A3[Brand colors]
  A --> A4[City]
  A --> A5[Style]

  B --> C[Scene description]
  C --> C1[Setting: city + landmarks + time/weather]
  C --> C2[Motifs: industry visual vocabulary]
  C --> C3[Style: medium + mood + abstraction + camera/lighting]

  B --> D[Composition for social background]
  D --> D1[Text-safe negative space region]
  D --> D2[Focal point placement + depth/blur]
  D --> D3[Contrast plan for readability]

  B --> E[Constraints]
  E --> E1[Aspect ratio token]
  E --> E2[Palette + dominance]
  E --> E3[No text/logos/watermarks]
  E --> E4[Clean background, export-ready]

  E --> F[Generate] --> G[Evaluate] --> H[Iterate small changes] --> F
```

The “generate → evaluate → iterate” loop is aligned with Google’s emphasis that prompting is iterative and you should refine until you get what you want. citeturn12view0turn13view0

### Ratio encoding: exact syntax and tokens

**Recommended prompt-level syntax (works across Gemini UI + API-based tools):**
- Put the ratio in a compact, unambiguous form near the end:  
  `"... 16:9 aspect ratio, widescreen backdrop"` or `"... 9:16 aspect ratio, vertical social post"`  
  This is consistent with DeepMind’s “prompt for production-ready specs” guidance. citeturn3view1
- If you’re using API configs, still consider leaving the ratio in the text prompt as a redundancy when the prompt also includes layout constraints (safe area). The API remains the strongest enforcement mechanism because it sets `image_config.aspect_ratio` explicitly. citeturn16view0turn4view0

**Officially supported aspect ratio tokens (Gemini API `aspect_ratio`):**  
`"1:1"`, `"2:3"`, `"3:2"`, `"3:4"`, `"4:3"`, `"4:5"`, `"5:4"`, `"9:16"`, `"16:9"`, `"21:9"`. citeturn16view3turn2view1

**Background-specific composition tip tied to ratio:**  
Google’s own “negative space background” template is ratio-agnostic—meaning you can keep composition rules (like “subject in bottom-right; large empty canvas”) and swap only the aspect ratio token. citeturn16view1

### Industry encoding: mapping inputs to motifs and vocabulary

Google’s official guidance doesn’t prescribe industry-specific motif dictionaries, but it does recommend being explicit about **what you want to see** in subject/setting and using detailed prompts to increase control. citeturn12view0turn12view2

In practice, industry is best encoded as a **motif bundle**: 2–4 concrete objects/materials + 1–2 abstract patterns + a tone. Keep the motif bundle subtle because these are backgrounds (not hero illustrations).

A rigorous way to encode “industry” is:

- Write `[Industry] brand background` + a short “visual metaphor” clause.  
- Add 2–3 “prop” nouns and 2–3 “material/texture” nouns.  
- Add 1–2 “diagram/pattern” nouns if you want an abstract techy feel, or 1–2 “fabric/light” nouns for lifestyle/fashion.

Examples of motif bundles you can reuse (recommendations; adapt as needed):
- Tech/SaaS: “abstract network lines,” “soft gradient mesh,” “glassmorphism panels,” “thin circuit traces,” “clean UI grid.”
- Cybersecurity: “subtle hex-grid,” “encrypted glyph texture (abstract, not readable),” “dark glossy materials,” “secure vault lighting.”
- Finance/Fintech: “calm geometric grid,” “subtle market-chart waves (non-numeric),” “polished stone/glass,” “architectural columns.”
- Healthcare/Biotech: “soft clinical light,” “bokeh microscopy shapes,” “clean white/teal palette,” “gentle organic curves.”
- Fashion/Luxury: “editorial studio backdrop,” “fabric folds,” “specular highlights,” “runway light bars,” “minimal set design.”
- Food & beverage: “macro texture,” “steam haze,” “ceramic/wood,” “warm appetizing light,” “bokeh café ambience.”

To keep this grounded in official best practices, treat these as **detail tokens** you plug into the “Style / Setting / Composition” structure DeepMind recommends. citeturn12view0turn12view2

### Brand colors encoding: notation and dominance enforcement

**What official docs support directly:** Google’s Gemini image-generation docs repeatedly use phrases like “color palette,” “color scheme,” and “palette,” indicating that describing palette intent is a supported and common pattern. citeturn5view0turn16view2turn5view3

**Recommended color notation in prompts (robust in practice):**
- Use **human-readable color names** plus **hex** in parentheses where possible; the name provides semantic grounding and the hex provides precision when the model/toolchain recognizes it. (Hex-code certainty is not guaranteed; treat it as a hint unless your tool documents it explicitly as supported.)
- Encode palette as a small, ranked list:
  - Primary (dominant): `electric blue (#0A84FF)`
  - Secondary: `deep navy (#0B1F3B)`
  - Accent: `warm coral (#FF5A5F)`

**How to enforce dominance (prompt mechanics):**
- Add a quantified dominance rule (heuristic) as a constraint line, e.g.,  
  “Background should be ~70% primary color gradient; accents limited to ~10% coral; avoid additional saturated hues.”
- Use a composition choice that makes dominance easy: “vast empty gradient canvas” (matches Google’s negative space template). citeturn16view1
- Apply a known color-hierarchy heuristic such as the 60-30-10 rule (dominant/secondary/accent) as a **guideline**, not a law. This is widely taught as a practical balance rule in design education. citeturn10search18

**Legibility note for overlays:** If you plan to place text on top later, enforce a “quiet” text-safe region and ensure foreground text will meet minimum contrast standards. WCAG technique guidance calls for at least a 4.5:1 contrast ratio between text and background for normal text. citeturn10search3turn10search7

### City encoding: landmarks, skyline, lighting, cultural cues

Google’s prompt guide explicitly recommends specifying setting and cultural cues when localizing (“regional cultural cues”) and also encourages using real-world locations/eras in prompts. citeturn12view0turn3view1

A city background prompt is strongest when you encode:
- **Anchor**: city name + one unmistakable landmark or skyline feature.
- **Context**: neighborhood/river/coastline + street furniture (subway entrances, trams, canals).
- **Lighting**: time-of-day + weather + color temperature (golden hour vs neon night).
- **Cultural cues**: subtle signage style (not readable text), architectural style, typical materials.

Example encoding pattern:
“Tokyo skyline with Tokyo Tower silhouette; rainy neon reflections; Shibuya-style crosswalk vibe; cool blue/purple gels; minimal readable text.”

If you want the model to *avoid* generating readable signage (common in city scenes), put “no readable text / no letters” in constraints. For tasks where you do want text, DeepMind advises enclosing exact text in quotation marks to improve precision. citeturn3view1turn16view2

### Style encoding: art styles, photography terms, mood, abstraction level

Official guidance encourages being explicit about whether you want a photo, an illustration, or a specific medium (“watercolor,” etc.), and using composition/camera language (wide shot, close-up, low angle). citeturn12view0turn8view0

A robust “style line” for social backgrounds typically includes:
- Medium: `photorealistic studio photo` / `flat vector illustration` / `isometric 3D render`
- Mood: `calm, premium, modern` / `energetic, playful` / `cinematic, noir`
- Abstraction: `minimal abstract` vs `high-detail photoreal`
- Camera (if photographic): `wide-angle`, `shallow depth of field`, `soft bokeh`, `tilt-shift`, etc. (Vertex/Imagen guidance lists common photography modifiers; the same vocabulary generally transfers well to Gemini image prompting). citeturn8view4turn8view0

For social backgrounds where text overlays happen in a design tool later, you usually want **controlled abstraction**: enough visual interest to feel branded, but not so much detail that text becomes unreadable. This aligns with established design guidance that negative space provides “breathing room” and improves clarity/hierarchy. citeturn10search1turn16view1

## Prompt templates and example prompts

### Concise prompt templates adaptable to inputs

Template for minimalist branded background with text-safe space (recommended default). This is directly inspired by Google’s negative-space background pattern, extended with city/brand constraints. citeturn16view1turn3view1

```text
Create a {RATIO} social background image (a {FORMAT_LABEL}) for a {INDUSTRY} brand.
Setting: {CITY}, featuring {LANDMARKS/SKYLINE_CUES}. {TIME_OF_DAY} lighting, {WEATHER} atmosphere.
Composition: large clean negative space on the {SAFE_SIDE} for headline text; focal elements clustered on the {FOCAL_SIDE}; background kept low-detail.
Color palette: primary {PRIMARY_COLOR_NAME} ({PRIMARY_HEX}) dominant; secondary {SECONDARY_COLOR} ({SECONDARY_HEX}); accent {ACCENT_COLOR} ({ACCENT_HEX}) used sparingly.
Style: {STYLE_WORDS}. Camera/lighting: {CAMERA_TERMS}, {LIGHTING_TERMS}.
Constraints: no readable text, no logos, no branding marks, no watermark; clean edges; export-ready.
{RATIO} aspect ratio.
```

Template for abstract gradient + pattern (high palette fidelity; low clutter).

```text
Generate an abstract branded background for social media.
A vast gradient mesh field dominated by {PRIMARY_COLOR_NAME} ({PRIMARY_HEX}), with subtle geometric {INDUSTRY_MOTIF_PATTERN} overlays.
Include a faint {CITY} skyline silhouette or landmark outline as a secondary layer (minimal detail).
Leave the {SAFE_SIDE} 40% of the frame as smooth low-noise negative space for overlay text.
Style: modern minimal, premium, high contrast control, no grain unless specified.
Constraints: no readable text, no logos, no watermarks. {RATIO} aspect ratio, {FORMAT_LABEL}.
```

Template for photographic city lifestyle background (when the brand wants realism).

```text
A photo-style social background image shot in {CITY} with {LANDMARK/NEIGHBORHOOD_CUE} in the distance.
Foreground: soft bokeh + shallow depth of field to create a clean text-safe region.
Lighting: {LIGHTING} with color grading biased toward {PRIMARY_COLOR_NAME} ({PRIMARY_HEX}) and {SECONDARY_COLOR} ({SECONDARY_HEX}); accent hints of {ACCENT_COLOR}.
Mood: {MOOD}. Composition: {SAFE_SIDE} negative space reserved for copy.
Constraints: no readable signs, no logos, no text. {RATIO} aspect ratio, {FORMAT_LABEL}.
```

## Best-practice rules, common pitfalls, and a testing checklist

### Best-practice rules for “social background” prompts

Keep the prompt structured like a creative brief: style/medium → setting → composition → palette → constraints. This matches Google’s framing of prompt components (style, setting, composition) and tends to reduce random “filling” behavior. citeturn12view0turn16view1

Make negative space explicit and measurable: reserve a side/region plus a percentage (“right 40–50% smooth negative space”). Google explicitly highlights a negative-space template as ideal for overlay contexts. citeturn16view1turn10search1

Always specify aspect ratio using the official token format:
- In prompt: “16:9 aspect ratio” + format label (“widescreen backdrop” / “vertical social post”). citeturn3view1  
- In API: `image_config.aspect_ratio="16:9"` (tokens listed in docs). citeturn16view0turn16view3

Use tight palettes and dominance language. Official examples encourage specifying “color palette/scheme,” and a dominance heuristic like 60-30-10 can help you describe intended weight distribution succinctly. citeturn16view2turn10search18

Protect legibility: If your workflow overlays text later, design for contrast. WCAG references establish minimum contrast expectations (commonly 4.5:1 for normal text), which is a good quality bar even when text is added outside the generator. citeturn10search3turn10search7

Iterate in small steps. Google’s official prompt guidance emphasizes iteration; Nano Banana workflows also support conversational editing so you can adjust composition, setting, or style rather than restarting. citeturn12view0turn18view1

### Common pitfalls and how to avoid them

Aspect ratio drift when you only imply shape. Fix by using explicit ratio tokens (“9:16 aspect ratio”) and/or API `image_config.aspect_ratio`. citeturn3view1turn16view0

Overly busy city scenes. Backgrounds should bias toward “suggestive” landmarks rather than hyper-detailed tourist posters—otherwise you lose text-safe space. Use the negative-space composition pattern as a hard constraint. citeturn16view1turn10search1

Accidental text/signage. City prompts often trigger signage; explicitly require “no readable text” unless you are intentionally generating typography. If you do need text, quote it (DeepMind guidance) and consider Nano Banana Pro for higher-fidelity text rendering. citeturn3view1turn16view2turn16view3

Palette mismatch. If you only provide hex codes, the model may not consistently honor them; blend names + hex + dominance + “avoid additional saturated hues.” (Hex reliability is tool/model dependent; verify in tests.)

Watermark expectations. Nano Banana images include an invisible SynthID watermark per Google’s official statements; you should avoid workflows that assume “no watermarking whatsoever.” citeturn11view0turn7view1

### Short testing checklist and evaluation metrics for output quality

The checklist below is deliberately short and repeatable; it maps directly to the five input dimensions you specified plus “background usability.”

| Check | How to test quickly | Pass criteria |
|---|---|---|
| Aspect ratio compliance | Inspect output pixel dimensions OR confirm API `aspect_ratio` setting | Exact target ratio (or within 1–2 px rounding) and no unintended cropping artifacts. citeturn16view0turn16view3 |
| Text-safe negative space | Overlay a grid or place dummy headline text in your design tool | Reserved region remains low-detail and supports readable overlay without adding opaque boxes. citeturn16view1turn10search1 |
| Brand palette fidelity | Sample 10–20 pixels in dominant region; compare to target hex ± tolerance | Primary color clearly dominates; accents are restrained; no “rogue” saturated hues. citeturn16view2turn5view0 |
| Contrast readiness | If overlay text is planned: run a contrast checker on representative background areas | Achieves at least WCAG-like contrast targets for intended text weight (commonly 4.5:1 for normal text). citeturn10search3turn10search7 |
| City recognizability | Show to a reviewer for a 3-second “guess the city” test | Correct city guessed ≥70% of the time (or the intended vibe is recognized even if landmark is stylized). citeturn12view0turn3view1 |
| Style adherence | Compare to a 3-image moodboard reference; check medium/mood/abstraction | Output matches requested medium (photo vs vector) and mood (cinematic vs airy) with minimal artifacts. citeturn12view0turn8view0 |
| “No text/logos” constraint | Zoom to 200% and scan high-contrast areas | No gibberish letters, no brand-like marks; clean background for reuse. citeturn3view1turn16view1 |
